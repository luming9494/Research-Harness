# WP-05 · Pi Durable 运行时验证

## 已验证的运行时边界

AXIOM 使用仓库固定版本的 Pi Durable 与 Node SQLite。原生 Pi CLI 继续提供交互和模型工具接口。当前新增的运行时入口可以打开一个独立任务目录，由 Pi Durable 管理任务检查点和调度。后续 Tiny CPU 接入时，Pi 会话 ID 用于审计关联，实验状态以领域账本为准。

| 文件 | 职责 |
| --- | --- |
| `runtime.sqlite` | Pi Durable 存储。Pi 管理任务状态、检查点和 memo。 |
| `owner.sqlite` | 进程所有权。打开运行时前通过独立 SQLite 写锁取得独占权，运行时关闭后释放。进程被强制终止时，操作系统释放文件锁。 |
| 现有 `summary.json`、实验记录与产物 | 展示与审计。接入后的预算及执行判定以事务记录和已核验的产物为准。 |

锁采用本地文件系统语义。同一目录的使用方都需通过 [AXIOM 运行时入口](../axiom/durable/task-runtime.ts)。本次测试验证单机进程崩溃恢复。

## 真实进程验证

```powershell
node --test tests/axiom/durable-runtime.test.mjs
```

测试进程创建任务，写入预留 82 步的执行意图，触发一个可观测的文件写入，然后等待。竞争进程尝试打开同一目录时收到占用错误。测试强制终止原进程，随后在新进程用相同任务 ID 打开 SQLite。Pi Durable 重新调度任务，探针遇到旧执行意图后返回 `needs_reconciliation`，保留原步骤预留。文件写入以独占创建方式模拟重复调用，测试证实恢复分支没有再次触发该操作。

这条回归会由 `npm run test:ml` 自动发现。探针使用模拟外部副作用，未训练模型，也未调用模型 API。测试中使用任务的原生数字 ID，后续用户命令接收字符串 ID 时须先校验和转换。

本轮离线构建与 `npm run check` 通过。`npm run test:ml` 共通过 75 项，包括 18 项 Python、41 项 Node 和 16 项 Pi Session 集成测试。

## 接入 Tiny CPU 的验收切片

1. 先把原 TaskSpec、原截止时间、候选身份和预算状态随任务保存。启动训练或模型请求前，先持久化执行意图和预算预留。操作结算后，持久化实际用量、指标凭证与产物摘要。
2. 在现有原生扩展提供显式恢复入口，按任务 ID 检查运行目录、实验记录和产物身份。已完成并核验的实验直接保留。外部状态或用量不明时保留预留并停止新增工作。
3. 以真实 Tiny CPU 训练验收。首轮完成后杀掉进程，恢复同一任务后只运行剩余候选，保留绝对截止时间和已结算用量，并独立重载最终交付。随后覆盖超时、有效产物丢失及正常取消。

当前已完成运行时接入验证。Tiny CPU 实验账本、CLI 恢复入口和完整任务恢复验收属于上述接入切片。
