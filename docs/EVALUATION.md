# AXIOM 低成本评测方案

> v0.3 · 2026-11-05 · **测试方案，不是已获得的实验结果。**  
> 核心目标：评估 AXIOM 是否在有限预算、明确规则下真正完成 ML 工程任务。

## 一、不能把真实训练一天当作日常回归

采用三层评测，配合无需 LLM 的单元测试：

| 层级 | 任务 | 单题时间目标 | 用途 |
| --- | --- | --- | --- |
| T1 | 训练代码错误、配置违规、日志/结果检查、来源校验 | 1–5 分钟 | 日常回归，CPU 优先 |
| T2 | 小型端到端模型改进、消融或运行/评估复现 | 10–30 分钟 | 里程碑回归 |
| T3 | 真实课程任务或较大规模论文实验 | 依专门预算 | 真实使用检验，非日常 CI |

时间是**设计目标，不是测得的承诺**。模型、电脑配置和数据量会影响实际耗时。

## 二、建议首批可复现任务

| 测试 ID | 任务说明 | 自动判定重点 |
| --- | --- | --- |
| T1-01 | PyTorch 数据类型或 Tensor Shape 故障 | 代码修复后测试通过 |
| T1-02 | 缺失依赖或错误路径 | 环境与路径约束均正确 |
| T1-03 | 明确禁止使用预训练权重 | Agent 不违反规则 |
| T1-04 | 指标来源丢失、评估协议不一致 | 不虚报可比性 |
| T1-05 | 短任务中断和有限重试 | 不重复/无限重启 |
| T2-OPT-01 | 小数据分类弱 Baseline 任务 | 真训练、独立验证、预算和最终产物 |
| T2-ABL-01 | 两个可开关模型模块 | 控制变量、缺失组合和报告 |
| T2-REP-01 | 轻量仓库可运行/评估复现 | 明确 Run/Evaluate/Train 级别 |

初期可考虑约 10 个 T1、3 个 T2、1 次单独 T3 演示。这是任务集**建设目标**，不是目前已经构建的任务集。公开测试只使用可再分发的合成样例或许可明确的数据。

## 三、每个任务的判题器

判题器必须独立于 Agent 的自我陈述：

- **代码可运行**：指定命令、单测和训练/评估脚本返回正确结果；
- **有效模型**：模型产物能加载，在定义好的评估集上运行；
- **任务达标**：按预先固定的验证口径计算结果（模型不保证一定达标）；
- **约束合规**：检查禁用模型/数据、代码允许修改范围、成本和实验次数；
- **证据链有效**：指标来自真实文件及正确的 Run、评估协议和版本；
- **停止条件正确**：目标、失败、预算耗尽、用户取消等状态能明确区分。

最终隐藏测试集只用于**最终独立判定**，不能反馈给 Agent 做多轮调参。

## 四、比较组与控制变量

| 组别 | 配置 |
| --- | --- |
| B0 | 原生 Pi，拥有同等受控工具环境 |
| B1 | Pi + 基础科研工具，但不启用任务级 Experiment Loop |
| AXIOM | Pi + TaskSpec + 预算控制 + 渐进式实验 + 证据验证 |

为公平比较，需要尽可能固定模型版本、任务说明、允许的工具/数据、CPU/GPU 环境、最长时间、最大模型调用/Token 和候选次数。每次从干净的 Git 提交和独立工作区开始；合理处理随机性，重要实验重复多次。

## 五、记录哪些指标？

- Task Success Rate / 达标率；
- Valid Model Rate / 有效模型率；
- Metric Delta / 相对合法 Baseline 的正式指标改进；
- Rule Violation Rate / 硬约束违规率；
- Completion under Budget / 预算内完成率；
- LLM Tokens、CPU/GPU 分钟、壁钟时间、估计 API/GPU 费用；
- Evidence Correctness / 指标来源准确率；
- 有限修复成功率、重复任务提交率。

按任务/候选/实验级别保存日志和成本。**性能提升与低成本两者都要衡量**，不能靠拒绝所有任务来刷低错误率。

## 六、记录格式（占位数据，仅供设计）

~~~json
{
  "task_id": "T2-OPT-01",
  "agent": "axiom",
  "status": "best_effort",
  "valid_model": true,
  "baseline_validation_metric": null,
  "best_validation_metric": null,
  "rule_violations": 0,
  "llm_tokens": null,
  "compute_seconds": null,
  "wall_seconds": null,
  "evidence_files": []
}
~~~

`null` 表示尚未测量或无可信来源；任何展示值都不应被解读为真实 AXIOM 成绩。

## 七、开发中的首轮评测顺序

1. 建立一个能够在 CPU 上运行的小型 PyTorch 基线；
2. 定义任务规则、数据分割与固定验收脚本；
3. 在不调用 LLM 的情况下把 Baseline、L0/L1 跑通；
4. 再接 Pi 的真实 Tool Calling 和代码编辑；
5. 做一次最小 T2 端到端优化，并保留失败轨迹；
6. 记录真实 Token/时间/结果，确定扩展规模是否值得。

禁止用 L2 Proxy 成绩代替正式成绩，禁止伪造实验日志，禁止把私有未发表研究直接放进公开基准。

**第一轮评测首先证明“可重复、能判断成功失败、成本可观察”，不强求漂亮的排行榜数据。**
