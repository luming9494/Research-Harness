# Research Harness / AXIOM · CLI-first 路线

> 以已固定的 Pi 1.5.0 源码为主体；不主动同步上游。新架构优先复用已有 Pi 机制，不重复造 TUI、Session 和基础 Agent Loop。

AXIOM 面向人工智能领域的工程与研究任务。机器学习是首个场景，当前实现以可信 Tiny CPU Optimize 为主。

## 当前里程碑

| 阶段 | 现状 | 接下来的判定标准 |
| --- | --- | --- |
| 新底座 | 本地完整构建、静态检查、离线 CLI RPC 启动通过 | 交互 TUI 人工验收仍待执行 |
| WP-01 | 独立 `.venv` 下真实 CPU 训练、Checkpoint 重载和评估回归通过 | 保持可复验回归 |
| WP-02 | 原生 Session/faux 工具注册、权限、Smoke、取消和工具恢复通过 | 保持原生工具回归 |
| WP-03 | 人工候选的真实训练、独立验证、keep 与失败 revert 通过 | 不将人工候选验收称作模型自主优化 |
| WP-04 | 可信 Tiny CPU 多轮内核已迁入，两阶段真实 LLM 主流程经原生 RPC 验收通过 | 补齐终端 TUI 人工验收，保留较差、平分和失败候选的离线回归 |
| WP-05 | 下一阶段。已有取消和失败回退覆盖，跨会话与重启恢复待实现 | 恢复时核验规则、预算与产物，保留历史最佳并防止重复执行 |
| 后续 | 规划中 | 第二类 AI 任务、跨任务评测、Ablate、Reproduce 和远程 GPU Runner |

## 最近优先级

1. **WP-05 任务可靠性与恢复**。先定义持久化状态和恢复协议，再接入可信 Tiny Task。恢复前核验原 TaskSpec、预算、实验记录和最佳产物。已完成的实验直接复用，状态或用量不明的在途操作暂停并报告。
2. **验证恢复与交付**。覆盖训练完成后重启、训练中断、模型用量未知、产物缺失或损坏。检查预算不会重置、已完成实验不会重跑、仍可交付经验证的历史最佳。保持构建、`npm run check` 和 `npm run test:ml` 通过，并补齐终端 TUI 人工验收。WP-04 结果见 [验收记录](AXIOM_VALIDATION.md)。
3. **梳理共用机制与领域规则**。从现有实现提炼任务、预算、执行、评估、证据和交付的共用边界。训练、Checkpoint 和 validation accuracy 留在 ML 实现里。
4. **验证第二类 AI 任务并扩充评测**。候选场景为小型 RAG 检索优化，用固定评测集、真实检索和预算内迭代验证共用机制。跨任务比较完成率、规则遵守、成本、恢复与证据正确性，再推进其他 ML 模式和远程 GPU。

## 新代码原则

新增模块前回答：

- Pi 当前源码是否已有对应能力？
- 是否能通过原生 Extension、Skill 或少量修改解决？
- 剩余问题由多个 AI 任务共享，还是只属于一个领域？当前实现能否为共用机制提供具体验证？

不为了“二开深度”而修改 Pi 底层 Agent Loop；只有明确的功能缺口和可复验的技术理由才动底层。
